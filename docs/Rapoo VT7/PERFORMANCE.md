# VT7 V2 性能设置调研

依据 2026-11-12 雷柏官方网页驱动脚本 `index-D1SIX0zk.js` 中的 VT7 V2 型号清单和 `VT_nrf54L` 实现整理。程序已支持 VT7 V2 有线与无线性能配置读写，并在写入后回读核对。

型号清单列出有线 PID `4660`、接收器 PID `1460`，性能配置使用 retail 档；射频协议选项仅在无线模式下提供，并要求接收器版本至少 0.74。这里列出的接收器 PID 与本机此前看到的 `1413` 接收器不同，不能简单视作同一个设备。

性能配置包含回报率和各回报率对应的传感器模式。模式码 0–5 分别是办公、均衡、火力、超核、竞技超核、狂暴竞技。官方提供的回报率原始码为 8、4、2、1、132、130、129；不同回报率允许的模式不同。型号清单没有启用独立的按键扫描率选项。

官方实现通过 Report 6 发送读取和写入请求，并通过 Feature Report 8 获取响应。配置地址依配置槽变化；读取和修改必须同步设备当前配置槽，且写入后必须重新读取核对。Windows HID 把这些报告分在不同集合；本项目当前的电量通道不能直接复用为配置通道。实现将配置读写串行化，选择同一物理设备的输出与 Feature 集合，限定配置命令和地址，不提供固件升级操作。

有线与无线配置查询及原值写入回读已实测：向 `FF00:000E` 发送官方 EEPROM 读取命令，再从 `FF00:000F` 获取 Feature Report 8，可以读取当前槽、回报率、传感器模式和射频策略。复现：`cargo run --example rapoo_perf_read`。工具自动选择有线或无线接口，默认只读；加 `--verify-write` 会将当前射频策略原值写回并核对。无线连接在发送配置命令前核验 Report 7 的鼠标 PID `4660` 和在线位；有线命令路由为 `FF`，无线为 `A5`。响应在当前 hidapi Windows 后端从 ACK 字节开始，而非报告 ID。

来源：[雷柏网页驱动](https://hub.rapoo.cn/)、[当时的官方脚本](https://hid.rapoo.cn/AHUB_WEB/dist/assets/js/index-D1SIX0zk.js)。

## 页面操作到设备写入的追踪

`Fre.O(mode)` 调用 `setSensorMode(rr(feature, reportRate), mode)`；`Sx.setSensorMode` 只写一个字节。配置槽 `s` 的基址为 `1536 + 1024*s`，模式表位于基址加 732，7 个字节分别对应 125、250、500、1000、2000、4000、8000 Hz。模式 0–5 对应办公、均衡、火力、超核、竞技超核、狂暴竞技。

槽 0、1000 Hz 的模式地址为 `0x08DF`。有线 Report 6 的原生写入包前缀为 `06 FF A5 01 DF 08 00 00 <mode>`，其余补零到 33 字节。页面切换模式没有调用 DPI、去抖、Motion Sync、射频策略或回报率的 setter。

回报率本身写到基址加 640；射频策略写到基址加 728；按键扫描率是独立字段，位于基址加 641。VT7 V2 的型号清单没有启用独立按键扫描率控件。切换回报率后，官方页面读取新回报率的模式字节；如果不在该档允许列表中，会写入该档允许列表中的第一个模式。

允许模式：125/250 Hz 为 0、1；500 Hz 为 0、1、2；1000 Hz 为 1–5；2000 Hz 为 2–5；4000/8000 Hz 为 3–5。这是页面对组合的约束，不能据此推导固件具体扫描帧率或功耗。

已获取官方 Nordic 固件清单，版本 1.45，文件 `mouse_nordic_l15_transparent_v1.45.zip`，含 slot0/slot1 二进制，每个 361529 字节。二进制可见 `sensor_motion`、`sensor_handler`、`keyscan_event`、`user_power_event` 等字符串，但尚未完成模式分支到传感器寄存器写入的反汇编追踪。不能将 UI 模式名称当作已验证的传感器参数组合。
