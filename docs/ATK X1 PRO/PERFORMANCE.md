# ATK X1 PRO 性能设置

协议来源：[ATK 官方驱动 3.2.27](https://bpcdn.atkgear.com/hub-v3/production/3.2.27/static/index-F-MYsmWR.js)。
2026-11-13 重新下载，SHA-256：`275EC10D7BF0916FEA8F27F6CC6415C3EFF6E02E682C8164E286626F0F394256`。

使用已有 FF02:0002 / Report 8 通道，17 字节报告。`Mo` 定义原生偏移：
命令 [1]、状态 [2]、大端 EEPROM 地址 [3..4]、长度 [5]、数据 [6..15]、校验 [16]。
全报告字节和模 256 为 0x55。GET EEPROM = 8，SET EEPROM = 7；GET 当前槽 = 14。
型号 GET = 16；包括有线在内，每次配置操作都核验 CID/MID 为 2/38。

| 字段 | 地址 | 编码 |
|---|---|---|
| 回报率 | 0 | 125/250/500/1000/2000/4000/8000 Hz → 8/4/2/1/16/32/64 |
| 传感器模式 | 185 | 基础/竞技/竞技增强 → 0/1/2 |

每个字段后跟独立校验字节 `(0x55 - value) mod 256`。官方对应 `j2`、`qu`、`At.Address`、`At.ReportRate`、`p2`。
只写目标字段和紧随的校验字节，不覆盖 DPI、按键、睡眠或其他设置。
当前槽写入前核验，写入后回读字段和完整性能状态；超时、错误状态、损坏校验不会显示保存成功。

界面按型号区分 ATK 与 VT7。1K 接收器和有线保守开放 125–1000 Hz；8K 接收器开放到 8000 Hz。
ATK 传感器模式是全局字段，不使用 VT7 的逐回报率模式表。自动切换目前仍仅支持 VT7 V2。

只读诊断：`cargo run --locked --example atk_perf_read`（默认无线，`--wired` 选择有线）。
以当前原值进行写入回读验证：追加 `--verify-write`。

## 2026-11-13 实机验证

当前连接 `373B:101A`（1K 接收器），型号核验成功。
读取配置槽 0，鼠标存储回报率码 64（8000 Hz），传感器模式 2。
高于接收器能力的存储值不代表实际无线回报率，界面单独显示保存值和当前连接限制。
`atk_perf_read --verify-write` 将当前回报率与模式分别原值写入，两次回读均与原值一致；未改变现有性能配置。
有线和 8K 接收器的性能读写尚未进行本轮实机验证。
